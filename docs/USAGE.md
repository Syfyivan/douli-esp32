# 豆梨：本机使用与开发

这是独立的个人语音助手项目，管理页面在 http://127.0.0.1:8788 。已加入 Orca 侧边栏。账号密码登录不启用；管理服务只监听本机，ESP32 连接独立的 8789 端口。

## 电脑试聊

1. 打开页面。聊天接入 DeepSeek 官方接口 `https://api.deepseek.com`；语音及辅助模型使用硅基流动，密钥保存在本机加密设置中：
   - 日常回答：`deepseek-flash`，关闭深度思考；复杂问题继续使用下方 Pro 深度思考配置。
   - 路由分类：2026-10-17 电脑端改用关闭思考的 `deepseek-flash`，结合上下文判断场景与复杂度。
   - 强模型：`deepseek-v4-pro`，开启深度思考；用于医学、学习、复杂分析及个人重要决策。官方接口的思考开关与硅基流动分别适配，工具查询后的继续回答会回传该轮所需的推理字段，不展示或朗读该字段。日常回复、历史工具查询及连续追问已通过真实接口测试；这不代表对模型质量的全面评测。
   - 识别：`Qwen/Qwen3-ASR-1.7B`。起初测试 SenseVoiceSmall，但连续两次 25 秒超时，因此改用 Qwen。
   - 语音合成：`FunAudioLLM/CosyVoice2-0.5B`，`claire` 音色，24 kHz 输出。
   - 报告图片识别：单独保留原来的 `Qwen/Qwen3.5-35B-A3B` 配置，避免文本聊天模型切换影响图片提取。
2. 在「对话记录」底部点击「电脑语音」，允许浏览器使用麦克风。后台自动化的点击可能不能解锁浏览器播放权限；页面会显示原因。
3. 说一句话，停顿后自动回复。可以点「说完了」提交，点「打断」停止回答，点「结束语音」释放麦克风。语音会话中也可发送文字。
4. 环境有回声时，先戴耳机试验。电脑端请求浏览器回声消除、降噪和自动增益，但实际效果取决于系统、麦克风和播放设备。
5. 点击「继续文字对话」展开输入框，或点击记录列表旁的加号新建文字对话。设置 → 模型连接 → 语音合成 →「保存并生成试听」提供独立的音色试听。
6. 单独说「晚安」「再见」「拜拜」「结束对话」「停止聊天」或「再见豆梨」，语音转写识别后立即结束本次语音，跳过模型回答和告别语音。支持「豆梨，再见」「再见啦，豆梨」、已配置的助手名字，以及现场确认的「都丽／都离」同音转写；兼容标点和空格。仍只匹配完整口令，「不要结束对话」「再见是什么意思」「再见，我还有个问题」等不会触发结束。浏览器立即关闭麦克风并停止排队中的播放；使用豆梨长连接固件的 ESP32 停止上传音频、清空播放并回到待机，保留后台连接。旧固件仍通过断开连接结束。也可以随时点击「结束语音」立即停止。

默认使用现有模型组合：识别支持转写预览或流式接口，回答文字和合成 PCM 分块输出，首个完整短句可先播放。声音检测默认使用 WebRTC VAD 并保留音量下限，支持对未完表达延长等待，以及短附和后继续回答。轻声、噪声与回声效果仍需实际麦克风验收。

通话中可分别静音麦克风、暂停播放、暂停／继续整个通话、开关字幕和结束通话。界面显示首音发送／播放等阶段耗时；有播放回执的客户端会记录已播完或被打断的段落，旧设备没有回执时只表示语音已发送。

配置独立的「画面理解」模型后，可主动开启摄像头或共享屏幕，每轮提问发送一帧，原图不保存。安卓 0.4.0 改用原生后台通话和屏幕共享服务；摄像头退后台停止。该版本尚待 realme 安装与锁屏、音频路由验收。

可选火山原生流式识别与全双工语音已接入，需自行开通对应服务并在本地模型设置填写凭据。默认模式不变；原生模式的复杂问题、记忆确认、设置修改和健康问答仍保留现有处理流程。配置、验证结果及实际使用限制见 [连续语音升级](VOICE_UPGRADE.md)。

等待说话的长段静音不会提交识别；检测到声音后保留一小段开头前的音频，减少漏掉首字。低于当前阈值的轻声仍可能漏检，需按实际麦克风试用。

## 日常配置

电脑端默认侧栏为「对话记录」「我的助手」「我的资料」「设置」。「我的资料」包含偏好与记忆、近期经历和健康资料。健康页用于整理报告和档案，历史问答仍可查看。「设备与家居」默认隐藏，在「设置 → 功能显示」开启；隐藏不会影响音箱连接和现有自动化。显示偏好及默认首页在当前客户端立即保存。

- **我的助手**：名字、人设、语气、长度、幽默程度、回避表达等填写后点击「保存偏好」。右侧「音箱音量」可读取已连接板子的当前音量，拖动滑杆后点击「应用音量」立即调整；也可直接说「音量调到百分之五十」。夜间模式开关、时段和音量比例会自动保存，切换页面不会丢失，失败会明确提示。夜间比例是在日常音量上进一步压低声音，不是板子扬声器的音量刻度。设置中的唤醒词只用于服务端处理设备上报的唤醒事件；不会替 ESP32 生成新的本地唤醒模型。电脑用按钮开始语音。
- **偏好与记忆**：明确偏好优先；自动提取只产生待确认建议，确认后才进入后续对话。保留原话和来源，冲突可选择替换，支持固定、更正、删除。现支持关键词与语义混合检索、相关性重排、带来源的近期摘要及历史查询；也可以在语音中提出记住、更正或忘记，再说“确认”。结构化事实、有效期、历史版本与后台整理详见 [记忆系统说明](MEMORY.md)。删除记忆会清理相关摘要和索引，并保留抑制指纹。
- 明确偏好可以直接修改。同一条事实重复提取时合并建议；更正来源原话后，相关记忆转为待复核，固定状态也不会跳过复核。
- **聊天记录**：按标题或内容搜索，导出 JSON，删除会话。删除时同时移除其未固定的来源记忆和保存的输入录音；固定记忆保留，来源可能显示已删除。
- **个人词典**：明确错误写法映射到正确词语。纠错产生的建议需要确认，不直接生效；默认不让模型重写口语。模型精修另行开关、另行配置。
- **模型路由**：支持日常、知识学习、解题、健康、辨析。自动模式使用“路由分类”模型结合最近对话判断场景、复杂度及个人重要决策，输出结构化分类；程序据此选择日常或强模型。分类模型留空时复用日常模型并关闭思考。医学、学习、解题、辨析、复杂问题和个人重要决策进入质量档；场景专用模型优先，其次使用“强模型”。强模型未配置时沿用日常并明确显示回退，不会把换提示词说成换了强模型。
- **连续追问与回退**：“继续讲”“举个例子”等明确追问沿用上一轮；其他表达交给分类模型结合上下文判断，明确换话题重新选择。手动模式优先；问候和简单设备指令跳过分类。分类超时、失败或把握较低时，默认优先强模型，可在设置中关闭这项偏好。分类等待上限、历史消息数可调。分类会增加一次模型调用；界面可展开查看实际返回模型、原因、耗时、思考请求与回退状态。分类把握不是答案准确率。
- **日常短句加速**：“你是谁”“你是什么模型”“你能做什么”“陪我聊聊”等完整、明确的日常短句直接交给日常模型回答，跳过云端分类，仍经过正常的记忆、工具和回答流程。支持礼貌开头、配置的助手名字及语气词；整句带有具体问题、引用、深入分析要求或其他补充时不按该规则放行。复杂问题自动切换和手动模式优先级保留。电脑端普通停顿等待已从 850 ms 调到 650 ms，未完表达仍可延长至 2200 ms；这些是当前本机配置，云端识别与合成波动仍可能造成等待，不能保证每轮固定延迟。
- **来源核查**：分类认为需要来源时，如已配置 Brave Key，会在回答前检索；没有 Key 或检索失败会明确告知回答模型并在页面显示。健康模式提供信息和就医问题整理，不作为确诊；辨析模式要求区分事实和观点。强模型和路由都需要实际场景评测。
- **联网**：可选 Brave Search Key。未配置就没有联网检索能力，不能把模型生成的链接当作已检索证据。不要为首轮试聊购买额外模型或数据库服务。

语音输入、历史上下文和必要偏好会发送给已配置的模型服务。录音默认不落盘；开启保存后只存用户输入 WAV。数据库没有自动上传。API Key、动作令牌和 HA 传感器令牌以 AES-GCM 存储，解密密钥与数据库同在本机 `.data`；这不防范能同时读取该目录的人。管理接口不会回显完整密钥。

## 语音调整助手

对话提示词按身份、运行信息、场景、输出方式、工具和相关记忆分层，具体见 [对话提示词](PROMPTS.md)。询问模型时依据本轮请求的模型标识回答；普通短问题允许一句结束，日常简短回复默认一到三句，要求详细时展开。网页文字与语音使用不同的输出格式，复杂问题自动切换模型仍保留。

唤醒音箱后，可以直接调整豆梨自身的设置，无需先在「设备与家居」创建动作：

| 说法 | 效果 |
|---|---|
| “声音大一点”“声音小一点” | 当前音箱音量增加或减少 10 个百分点，限制在 0–100% |
| “音量调到百分之五十”“现在音量是多少” | 指定或查询当前音箱音量 |
| 调节后紧接着说“再大一点” | 两分钟内沿用上一条音量调整；普通聊天中的“大一点”不据此修改设置 |
| “以后回复简短些”“以后回答详细一点” | 保存回复长度，后续对话生效 |
| “说话温柔一点”“轻松幽默一点”“直接简洁一点” | 保存语气、必要时同步调整幽默程度或回复长度 |
| “以后像朋友一样聊天，少一些客套话” | 用日常模型识别更自由的风格要求，校验后保存 |
| “换个回复风格” | 先询问具体风格，收到选择后再修改 |

音量只作用于说话的那台音箱。支持 MCP 音量工具时，先读取板端音量，再设置并读回核实；当前固件会保存非零音量。音量设为零可静音，“取消静音”恢复此前音量；当前固件重新上电时会把零音量恢复为 10。旧设备没有该工具时使用当前音箱的服务端播放音量，并即时生效。原有服务端增益和夜间音量仍会叠加，不等同于扬声器音量百分比。

回复风格沿用全局「我的助手」设置，文字与语音对话均可修改。该页面每五秒刷新已保存设置，表单只提交手动改过的字段，避免覆盖同时发生的语音调整。设置指令记录在聊天历史中，但不进入个人记忆提取和经历摘要。普通提问、转述、假设和否定修改不执行设置；未识别清楚时询问具体要求。设备无响应或读回不一致时明确告知未核实，不口头宣称成功。

本次已用真实 DeepSeek Flash 验证自由表达识别，并通过当前音箱 MCP 接口完成 70→69→70 的实际音量读写和复核。ASR→设置执行→语音确认→后续风格使用已通过协议测试；这些证据不代替真人唤醒、口令识别与听感试用。

## ESP32 接入

1. 目标设备是微雪 ESP32-S3-AUDIO-Board。有麦克风、扬声器，固件必须支持小智 WebSocket 协议以及修改 OTA 服务地址。
2. 电脑和设备接入同一局域网。先在「设置 → 功能显示」开启「设备与家居」，再进入该页查看电脑局域网 OTA 地址，例如 `http://电脑局域网IP:8789/xiaozhi/ota/`。不要选 VPN/虚拟网卡地址。
3. 开启配对窗口，把地址写入设备固件配置。设备首次出现后，对照设备播放或显示的配对码，在本机页面批准对应设备。支持小智激活流程的固件会轮询激活状态，批准后自动重新请求 OTA；其他版本可能需要重启设备。
4. 如 Windows 防火墙阻止连接，只按实际网络范围为设备端口放行；管理端口仍仅供本机使用。电脑需保持运行，休眠时无法提供服务。
5. 真机核对采样率、麦克风方向、音量、唤醒、连续对话、回声和打断；当前协议测试不能代替这一步。

已批准的设备卡片也提供「应用音量」与「读取当前音量」，与「我的助手」操作同一台音箱，支持硬件音量工具时设置后会再次读回核实。展开「这台设备的语音设置」可设置对话模式、播放音量比例和收音阈值；这里的播放比例是额外降低输出强度，夜间还会叠加夜间比例。阈值留空跟随全局；较小值容易收进轻声，也更容易被噪声触发。展开区域的设置保存后，设备重新连接生效；尚未结束且未超过 30 分钟活动期限的会话可继续。

到货准备：先用可传数据的 USB-C 线接电脑，核对开机提示和串口，再决定是否刷写。官方适配目标为 `esp32-s3-audio-board`；不要选择其他屏幕板的固件。参考 [微雪小智教程](https://docs.waveshare.net/ESP32-S3-AUDIO-Board/XiaoZhi_AI/) 与 [适配列表](https://docs.waveshare.net/ESP32-S3-AUDIO-Board/ESP32-AI-Tutorials/)。设备服务地址为 `http://电脑局域网IP:8789/xiaozhi/ota/`；普通家庭 Wi-Fi 配对优先使用 WLAN 地址，不使用 Tailscale/VPN 等虚拟网卡地址。IP 可能变化，以设备页和本机网卡为准。

助手名称「豆梨」已经写入服务端设置；固件的本地唤醒词是另一项配置，不会随着页面改名自动改变。

真机接入记录：Windows 串口已识别该板，原装小智 2.4.2，2026-10-15 更新官方 2.5.2，10 月 16 日更新为豆梨长连接固件 2.5.2.1。设备已连接家庭 Wi-Fi 并完成本机 OTA 配对。配网热点名形如 `Xiaozhi-XXXX`，配网页面 `http://192.168.4.1`，完成联网后热点关闭；电脑或手机均可配网，电脑配网完成后应切回家庭 Wi-Fi。Windows 防火墙规则应仅允许实际家庭网段通过 WLAN 访问本机设备端口 8789 的 Node 进程；IP/网段改变时需更新规则。管理端口 8788 仍仅监听回环地址。具体设备编号和网络地址不随仓库发布。

2026-10-15 已修复原机损坏的资源分区，板端实际加载 MultiNet7 中文模型与「你好豆梨」唤醒配置。先在约半米处说「你好豆梨」，停一下再提问；用户已确认免按键唤醒并听到回复，串口和后台也记录到完整对话。单说「豆梨」不是本次板端配置的完整唤醒口令，页面改名也不会自动改动固件。短按 BOOT 仍可发起对话，无需等待提示音。

豆梨长连接固件 `2.5.2.1` 开机联网后自动连接后台。待机时只在板端检测「你好豆梨」，不上传麦克风音频；每 30 秒通过心跳维持连接。唤醒后沿用已建立的连接开始对话。网络或后台中断后自动重试，失败间隔从 5 秒逐渐增加到最多 60 秒；电脑仍需开机且后台运行。待机灯光沿用原固件的渐灭，等待用户说话时为红灯。

电脑后台配合固件 `2.5.2.4` 支持播报时插话：直接说补充、纠正或下一个问题，检测到持续声音后先停止原回答，再识别并处理新内容；无需再次说唤醒词。说「再见豆梨」也是先打断，识别出结束口令后立即回到在线待机。后台使用经过板端回声消除的声音，保留插话开头的短缓存；识别仍需等待停顿和 ASR，因此“停止播报”与“识别出新问题”是两个时刻。旁人持续说话也可能触发打断。当前用户选择仅更新电脑与板子，手机旧版后台未包含此次修复；保持固定电脑模式使用。实际测试范围见 [FIRMWARE.md](FIRMWARE.md)。

ESP32 唤醒后，连续 30 分钟未检测到达到收音阈值和最短时长的说话，会静默停止音频上传并回到待机，保留后台连接；下次需要再次说「你好豆梨」或短按 BOOT。静音音频、低于阈值的背景声和网络心跳不会重新计时。检测到有效声音或完成一次回复后重新计时，识别、思考和播放期间不触发静音待机。服务每 30 秒检查一次，实际待机可能比 30 分钟晚最多约 30 秒。该规则只用于 ESP32，电脑后台继续运行；说结束口令仍可立即结束。声音判断沿用现有音量阈值，持续高于阈值的噪声也可能延后待机，实际环境需要按设备调节收音阈值。若固件没有声明长连接能力，或没有在 5 秒内确认停止上传，后台会断开连接作为兼容回退。

音箱的「对话记录」按一次唤醒交流分段：从唤醒开始，到结束口令、手动待机或超时待机结束，中间多轮问答、短暂停顿和打断属于同一个 session。下一次唤醒开始新会话；第一句非空语音转写出现后才保存记录，仅欢迎语或空识别不会留下空会话。未结束的交流在短暂断线后可继续，断线期间心跳不会延长 30 分钟活动期限。新会话不自动带入上一段的聊天上下文，仍可使用已保存的跨会话记忆；记忆继续按完整问答轮整理。升级前的历史记录保留原样，不自动拆分，首次新交流从新会话开始。

首次激活后的崩溃在单独升级后仍复现过；本机激活接口改为无正文响应后，连续 4 次真机重新激活无崩溃或软件重启。长期稳定性、回声和打断还需实际使用验证。原版固件待机时可能显示未建立 WebSocket；豆梨长连接固件在待机时也保持在线，不需反复配网。固件补丁、构建与验证边界见 [FIRMWARE.md](FIRMWARE.md)。

刷写前完整备份及校验清单保存在本地 `.data/device-backups/`。10 月 15 日修复写入应用和资源分区；10 月 16 日长连接更新只写应用分区，保留原 Wi-Fi、OTA 配置和唤醒资源。下载校验、资源构建和复测记录在 `.runtime/firmware-repair/`，这些文件均不纳入 Git。不要随意用其他型号的整片镜像覆盖本板。

实现的是 OTA **服务发现**，返回 WebSocket 地址和设备凭据；没有固件镜像分发或在线升级管理。现有固件若没有自定义 OTA 地址入口，到货核对版本后再确定刷写步骤。配对和 OTA 引导适用于可信私人局域网，未实现硬件身份的密码学证明，不开放到公网。

设备协议：`hello`、`listen start/stop/detect`、`abort`、`stt`、`tts`，Opus 音频 v1/v2/v3，MCP 工具发现和调用。短暂断线只延续尚未结束且未过期的会话；`listen stop` 表示本轮说完，不结束整个会话。设备密钥只在 OTA 配置中下发，管理界面不显示。后台工具必须由设备声明，动作返回「收到指令」与「状态已核实」两种不同结果。

## Orca 电脑任务

在电脑端「我的助手 → 电脑任务」开启「允许豆梨调用本机 Orca」，点击「检查连接与项目」，选择默认工作区并保存。电脑需运行 Orca，工作区已经登记，Codex 可以正常登录使用。Windows 默认查找 Orca 安装目录中的 `resources/bin/orca.exe`；自定义路径也必须指向原生 CLI，不接受 `.cmd`、`.bat` 或 PowerShell 脚本。当前接入的是 Orca 内的 Codex，不是独立 ChatGPT 应用或通用桌面鼠标控制。

可以直接说或输入：

- 「让 Orca 在豆梨项目里检查测试覆盖，先给我建议，不要改文件。」
- 「刚才的电脑任务怎么样了？把结果告诉我。」
- 「让刚才的 Orca 任务继续，补充一份修改方案。」
- 「停止那个电脑任务。」
- 「看一下 ESP32 项目在 Orca 里现在有多少个 session？」
- 「读一下 Orca 里标题包含‘调研工具记忆系统方案’的会话。」
- 「在 Orca 里‘调研工具记忆系统方案’这个 session 接着讨论，结合刚才的结论给我一个实现方案，先不要改代码。」

已有会话查询直接读取 Orca 当前项目下的会话终端，包括用户自己创建的会话，与「豆梨跟踪的任务」列表分开。支持用 `ESP32`、`豆梨ESP三二` 等名称唯一匹配 `douli-esp32`；多个工作区匹配时需要明确选择。查询可返回标题、数量和连接情况，指定会话后可读取最近终端画面。当前范围不包含已关闭或归档的历史；连接正常也不代表 Agent 正在工作。开发接口是 `GET /api/computer/sessions?project=ESP32` 及 `GET /api/computer/sessions/:sessionId?project=ESP32`；连接失败返回错误，不伪装成零会话。

用户明确指定已有 Codex 会话并要求继续时，豆梨在该会话内发送后续要求，保留原上下文，并新增一条任务跟踪记录；不会另建终端或复制对话。之后可查询结果、继续追问或停止这项任务。仅查询或读取会话不会接管它，询问「能不能继续」也不发送指令。同名会话需明确选择；Agent 必须已确认空闲，会话忙碌、等待权限或身份变化时本次不发送，也不会排队到稍后自动补发。提交结果不确定时保留记录，不重复发送。已有个人会话保留在 Orca 中，豆梨不提供关闭它的操作。开发接口是 `POST /api/computer/sessions/:sessionId/continue`，请求体含 `project`、`instruction`、`requestKey`，重试必须复用相同请求编号与内容。

页面也可创建任务、查看最近输出、发送追问、停止任务和关闭豆梨新建的 Orca 会话。多个任务时需要明确目标。新任务会另建一个后台 Codex 会话；明确要求继续已有会话时沿用用户指定的会话。项目未明确时使用保存的默认工作区。任务可按用户要求修改该工作区，因此需要在请求中说清楚检查范围、修改约束和验收条件。登录、权限确认等需要在 Orca 中处理，豆梨不会代批。

任务与语音 session 分开保存：结束聊天、下一次唤醒或删除聊天记录不会取消任务；重启豆梨后继续查询原会话，不重新执行。关闭 Orca、Agent 进程退出或身份变化会影响后续操作。CLI 暂时不可达时保留原任务状态并显示连接错误，不把断线当成完成；提交结果不确定时显示「提交待核对」，不自动重发。相同请求编号复用同一次创建/追问；「正在停止」只表示已请求中断，收到中断证据后才显示「已停止」。关闭会话保留豆梨中的任务记录。

「本轮已返回」表示 Agent 已结束当前一轮，不等于业务目标或代码质量已验证。页面显示的是最近终端画面，长输出可能截断；完整过程可到 Orca 查看。任务结果在页面刷新，语音中可询问进度并播报结果；当前不会在待机时主动唤醒音箱播报。

电脑控制配置、任务、会话身份和请求去重记录使用本机加密存储，不随电脑/手机数据同步，也不写入个人记忆提取。手机后台不直接控制电脑上的 Orca。接入使用 [Orca 官方 CLI](https://www.onorca.dev/docs/cli/overview)，调用过程不经过系统 shell，不把用户文字拼成命令。

2026-10-17 在 Windows、Orca 1.4.218 上验证了真实模型创建、结果查询、跨聊天追问、中断，以及豆梨后台重启后同一任务继续运行；合成语音经过真实 ASR、任务查询和 TTS 返回非静音音频。自动化测试另覆盖断线、重复请求、身份变化和来源保护。这些不代表其他平台、任意 Agent、复杂任务质量或真人音箱端到端验收。首次启动的 `tui-idle` 检测可能超时，适配器仅对已确认 Codex 身份且出现明确空提示符的情况做启动兼容；其余启动/登录提示等待用户在 Orca 处理。

同日验证了已有会话续聊：先在临时 Codex 会话中记住测试编号，再由没有该任务记录的豆梨实例通过真实模型按标题继续，未在新指令中重复编号，仍正确返回原编号；重启豆梨实例后再次追问保持同一个终端和任务。测试会话已关闭，原有会话保留。Orca 的自动会话标题可能在首次回复后继续变化；标题无匹配或不唯一时重新查询列表，不猜目标。已有会话续聊必须取得空闲信号，不使用首次创建时的空提示符兼容逻辑。

## 家居与传感器

- 手指机器人尚未指定具体型号。拿到开放 API 文档后，分别登记「开灯」「关灯」两个动作；HTTP、Home Assistant 服务、ESP32 MCP 工具三种方式已实现。实际能否按动大翘板、供电和力度仍需要真机确认。
- HTTP 请求可配置地址、方法、JSON 请求头/内容。HA 动作可填实体、服务、预期状态，执行后独立读取状态核验；没有独立反馈的机器人只能报告指令已被接收。
- 同一轮回答重复调用同一个动作 ID 时，后端复用第一次执行结果，避免模型重复按开关。这不跨对话轮次去重，也不能保证机器人端自身不会重复执行。
- 传感器可由已授权 ESP32 请求 `POST http://电脑IP:8789/sensors/传感器ID`，头部含 `Device-Id`、`Authorization: Bearer 设备令牌`，JSON 内容为 `{"value":42}`。令牌与 OTA 返回一致。给设备增加实际传感器驱动需要按到货硬件实现。
- 也可登记 HA 服务地址、实体 ID、长期令牌，每 30 秒读一次数字状态。失败不会刷新时间戳；非数字状态不用于数值规则。
- 定时、传感器阈值规则默认关闭。阈值触发后需回到另一侧才再次触发，设有冷却间隔；数值超过两分钟未更新时不触发。规则只在本机服务运行时执行，停机错过的时间不会补执行。

## 开发与独立启动

需要 ESP32 在不同 Wi-Fi 下连接这台电脑时，参见 [跨网访问](REMOTE_ACCESS.md)。已配置的入口使用 HTTPS/WSS 和设备令牌；电脑后台需要保持运行，板子待机仍保持连接。

需要 Node.js 22.13+（本机已验证 22.14），SQLite 使用 Node 自带模块，Opus 使用 WASM，不需要 MySQL、Redis、Python 或 FFmpeg。

```powershell
npm ci
npm run build
npm run start:background
```

关闭：`npm run stop`。开发前端：先启动后端，再 `npm run dev`，前端地址为 http://127.0.0.1:8790 。构建结果由 8788 服务提供。

独立启动器使用 detached 子进程、隐藏 Windows 窗口、文件日志，避免临时终端退出时连带关闭。`.runtime/process.json` 保存 PID，停止脚本先校验进程命令路径再停止。该方式不是开机自启。Windows/macOS 路径均用 Node path API，macOS 停止脚本使用 `ps`；目前只在 Windows 真机运行过。

环境变量：`DOULI_PORT`、`DOULI_DEVICE_PORT`、`DOULI_DEVICE_HOST`、`DOULI_DATA_DIR`。浏览器来源保护目前只允许默认 8788/8790 端口；如更换管理端口，需要同步修改来源白名单。

目录：

- `server/`：协议、对话、输入、记忆、数据库和家居。
- `web/`：React 界面，AudioWorklet 采集、流式重采样、WebAudio 播放。
- `tests/`：隔离临时数据库和模拟服务的集成检查。
- `scripts/`：启动、停止和显式触发的真实模型检查。
- `.data/`：本机数据和密钥，忽略于 Git。
- `.runtime/`：日志、PID、测试音频和检查结果，忽略于 Git。

## 检查

`npm test` 不调用收费模型、不控制真实设备。覆盖协议编解码、拒绝未授权连接、API 来源保护、设置持久化与脱敏、原文纠错、记忆冲突、来源清理、工具动作判断、自动化、HA、打断和识别回退。

真实模型检查会调用已配置服务：

```powershell
node scripts/check-models.mjs
node scripts/check-voice.mjs
node scripts/check-memory.mjs
node scripts/check-routes.mjs
node scripts/check-routing.mjs
```

第一个生成短语音再转写；第二个把生成的音频送进完整 WebSocket 对话流程，保存返回音频并删除临时会话；第三个在隔离临时数据库中检查真实模型记忆提取、来源、确认、重开和新会话召回，完成后删除临时资料。这些不是真人录音、跨日效果或 ESP32 验收。

第四个用隔离数据库检查自动解题/健康/辨析路由和手动切回日常模式，报告保存在 `.runtime/route-check.json`。样例不会进入个人聊天或记忆；路由检查成功不代表模型所有事实正确或具备临床诊断能力。

第五个检查真实分类模型的十二个样例（含知识学习、健康、追问、换话题、手动覆盖），再执行学习→追问→闲聊的完整真实模型对话。使用隔离数据库并关闭记忆提取、向量检索和摘要任务；报告保存在 `.runtime/routing-check.json`，不写入个人聊天。它会调用收费接口；测试只证明这些样例的路由与请求链路，不是总体准确率、医学质量或硬件验收。

完整验收状态见 [DELIVERY.md](DELIVERY.md)。Typeless 静态分析依据见 [typeless-research.txt](typeless-research.txt)。第三方来源与许可见 [THIRD_PARTY.md](THIRD_PARTY.md)。

## 可选流式 ASR 桥接协议

`settings.input.streamingUrl` 接受自建桥接服务；不能直接填写其他产品的私有接口。

- 客户端先发 `{"type":"start","id":"唯一ID","sampleRate":16000,"channels":1,"context":"JSON上下文"}`。
- 后续二进制帧为单声道 16 kHz PCM16LE，默认每 3 秒分块发送；结束前发送剩余音频，再发 `{"type":"stop","id":"同一ID"}`。
- 服务端发 `{"type":"partial"或"final","id":"同一ID","text":"识别结果"}`；错误为 `{"type":"error","id":"同一ID"}`。
- 等待最终结果超时或流式连接失败时启动一次 HTTP 回退；先得到有效结果的一方获胜，取消另一方，忽略不匹配的 ID。

当前直接模型适配器使用兼容 `/chat/completions`、`/audio/transcriptions`、`/audio/speech` 的接口。未实现所有厂商的实时音频协议或自动供应商切换。

## 选择 ESP32 连接的后台

打开「设备与家居 → 我的 ESP32 → 板子连接哪个后台」，选择固定电脑、固定手机或自动选择，再点击「应用连接方式」。如果没有设备入口，先在「设置 → 功能显示」开启「设备与家居」。页面会显示实际连接及板子确认结果。

固定手机需手机服务运行且与板子在同一局域网；自动模式在新建连接时优先电脑，失败后尝试手机。切换会结束当前对话，初次切换失败会恢复原设置。当前这块板子默认已恢复固定电脑，继续使用已配置的公网连接。配对、地址变化及跨网边界见 [BACKEND_SELECTION.md](BACKEND_SELECTION.md)。
