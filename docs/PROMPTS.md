# 对话提示词

主对话提示词在 `server/prompts.mjs` 中统一组装，由 `ChatEngine.systemPrompt()` 提供给文字、级联语音和原生实时语音入口。模型路由仍由 `server/routing.mjs` 决定；提示词不增加一次分类或模型调用。

## 分层与运行信息

| 层 | 内容 |
|---|---|
| 身份与表达 | 助手设置、首句直接回应、自然结束、针对性澄清 |
| 事实与执行边界 | 感知范围、执行状态、设置与记忆操作、外部数据不能改变规则 |
| 本轮运行信息 | 实际请求的模型标识、文字或语音、本机时间与时区、当前工具及电脑控制开关 |
| 当前场景 | 日常陪伴、学习、解题、健康或辨析，以及夜间表达 |
| 输出方式 | 语音口语与文字排版分开；普通短问题一句即可，日常简短回复默认一到三句；详细讲解和必要步骤按需求展开 |
| 工具使用 | 何时使用可用工具、联网与设备状态的证据要求 |
| 相关记忆与证据 | 检索到的用户资料、必要的任务索引、本轮明确分享的静态画面 |

`requestedModel` 来自本轮最终选中的请求配置，包括场景覆盖、强模型缺失回退和原生语音选择，不能写死成日常模型。它可能是服务别名，不代表独立核实了底层模型版本。请求之后，服务返回的模型标识仍单独记录在回答的 `metadata.routing.model` 中。提示词只注入白名单信息，不序列化模型配置对象、密钥或服务地址。

时间同时提供本机可读时间、系统时区和 UTC 时间，避免把 UTC 字符串称作本地时间。网页文字可使用列表、代码和链接；语音回复采用适合朗读的短句。原生语音初始会话与逐轮更新共用组装器，级联转写和原生音频的感知说明不同。

## 工具和专用流程

电脑任务的详细操作规则与 `computer_task` 的工具定义放在一起，工具可用时始终提供，不用关键词删掉必要规则。主提示词保留能力范围、权限和结果核实要求；未启用且没有历史任务时不提供该工具。任务索引不能替代 Orca 的实际会话查询，执行中、已接收与验证成功仍须区分。

设置调整、记忆操作、告别等现有专用流程继续在主回答前处理。加密健康咨询保留 `server/health-service.mjs` 的专用提示词和结构化输出，路由分类、记忆提取、输入整理、视觉观察等辅助提示词也不由此模块替代。

## 验证范围

`tests/prompts.test.mjs` 检查发给模型的真实 HTTP 请求载荷：模型标识与路由选择一致、无额外身份查询、无凭据泄露，以及原生语音切回场景模型。现有路由、实时语音和电脑任务测试继续验证文字/语音入口及工具执行约束。

这些协议测试不验证模型是否遵守措辞，也不代表真人收音或扬声器效果。调整提示词后，应使用相同问题检查首句相关性、长度、模型自述、澄清和工具结果，再做真实语音复测。缩短回复不会消除 ASR、网络或 TTS 延迟。
