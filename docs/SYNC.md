# 手机、电脑与 ESP32

两端运行同版本豆梨，连接同一个局域网。在已有资料的设备「设备与家居 → 手机与电脑同步」生成配对信息，在另一端粘贴并配对。一次性配对信息有效期十分钟，不要发送给其他设备或保存到仓库。首次加入采用发起端的模型与助手配置，再合并两端用户资料。

## 数据

同步聊天、记忆及其证据/遗忘记录、带日期的经历及来源/上下文依赖、个人偏好、词典、模型与语音配置、健康档案与报告原件、ESP32 授权。音频、任务队列、回顾摘要、向量索引、运行日志及设备在线状态的判断留在本机；经历回顾和派生索引由各端重建。增量记忆增加了同步表和字段，配对两端需使用相同版本，旧版与新版的不同数据结构不能直接交换。

每行使用逻辑时钟和设备 ID 确定修改顺序。不同记录可合并；同一记录离线同时编辑时，按逻辑时钟及设备 ID 确定一个版本，**没有逐字段合并或冲突版本历史**。建议不要两端离线同时修改同一份档案。远端更新后，本机旧编辑表单不能继续覆盖，必须刷新。

删除保留同步墓碑，优先于旧设备后发来的修改，避免聊天/记忆/报告复活。删除 ID 不复用。同步是资料副本，不替代备份；离线设备在重新联网同步前仍可能保有旧副本。

传输使用 AES-256-GCM，配对和交换使用不同派生密钥；请求带时钟范围、一次性请求 ID 和对端身份校验。局域网 HTTP 只运输密文，不开放远程管理页面。配置密钥和健康内容在接收端用自己的本地密钥重新加密。断开同步停止本机参与，保留本机资料，并不远程擦除另一端。

## 自动连接

配对后产生共享名称 `douli-xxxxxxxx.local`。在 ESP32 中把 OTA 服务地址设置为界面显示的 `http://共享名称:8789/xiaozhi/ota/`；两端要使用相同设备端口。

UDP 8791 发送带认证的可用性广播，共享 mDNS 名称由当前优先主机回答，各后台另回答自己的 `douli-node-<节点 ID 前八位>.local` 名称。电脑优先级 20，手机 10；失去广播约 9 秒后重新选择。首次同步未完成的主机不参加接手。已健康连接的 WebSocket 不被强制搬迁。固件 2.5.2.3 可直接在页面选择固定电脑、固定手机或自动模式，使用独立节点名称和私人 IP 备用地址，详见 [BACKEND_SELECTION.md](BACKEND_SELECTION.md)。

这依赖路由器允许组播、系统防火墙及 ESP32 固件支持 `.local` 解析并在重连时重新解析。仅启动发现服务不证明设备已完成切换。手机需保持前台服务和 Wi-Fi 可用；不同 Wi-Fi、访客隔离网络、电脑/手机都关闭时均无法自动接手。当前不提供互联网中继同步。

本机 Windows 已有 TCP 8789 家庭网段规则；新增 UDP 5353/8791 规则仅允许 `192.168.0.0/24` 到当前 Node 程序。换网段或 Node 路径需要相应调整。没有关闭 Windows 防火墙。
