## 行为与协议

- 开机联网且激活完成后，在独立任务中连接 WebSocket；待机时仍运行本地唤醒检测，不运行语音上传。失败后按 5、10、20、40、60 秒间隔重试，避免阻塞主循环和音频任务。
- 双方 `hello.features.persistent_connection: true` 才启用长连接。后台每 30 秒发送 JSON `ping`，固件回复 JSON `pong`，同时刷新固件原有的接收超时。MQTT 和未声明能力的旧固件保留原来的连接语义。
- 后台发送 `{"type":"session","state":"standby","reason":"farewell|inactivity|manual"}` 后，板端关闭语音处理、清空待发音频与播放队列、进入 idle 并确认 `{"type":"session","state":"standby"}`。5 秒没有确认则断开连接。待机期间服务端也拒绝处理音频；新的 `listen start/detect` 恢复对话。
- 「再见豆梨」等结束口令在 ASR 得到结果后直接进入待机，不调用回答模型或播放告别。兼容现场已确认的同音转写「都丽／都离」、名字前后换位、常用句末语气词及已配置的助手名字；仍只匹配完整口令，不把否定、询问或包含这几个字的普通话语当作退出。30 分钟静音规则继续生效。开机/重连默认待机；唤醒才上传音频。
- `2.5.2.4` 为此板型启用 `USE_DEVICE_AEC`，会话采用 realtime 收音模式，播报时继续发送回声消除后的音频。WS/MQTT `hello.features.device_aec: true` 明确表示板端已处理回声，保留原来的服务端 AEC 字段语义。电脑后台据此允许语音插话；未启用 AEC 的旧 ESP32 不因扬声器回声触发能量打断。
- 后台把 WebSocket 连接与历史 session 分开：一段唤醒交流使用一个 session，结束后下一次 `listen start/detect` 换新 ID。同一连接的后续事件会携带新的 `session_id`。设备元数据 `voiceSession` 保存 ID、是否结束、是否已写入历史及最近活动时间；连接刚建立时只预留 ID，第一句非空转写才创建历史记录。重连的首次 standby 确认只确认停止上传，不结束尚未过期的旧交流；后续设备主动 standby 和后台请求待机都会结束会话。旧固件没有主动待机通知时，普通断开仍按网络中断处理，明确结束口令和服务端超时仍会结束会话。
- 插话检测在 16 kHz PCM 上累计至少 140 ms 超过收音阈值的声音，容忍小于 100 ms 的音节间隙，保留最多 200 ms 的起始缓存。检测后立即取消旧生成/合成并发送 `tts/stop` 的 `interrupted: true`；固件清空解码和播放队列、拒绝被取消的音频并保持收音。随后按原有停顿与 ASR 流程处理补充/纠正或结束词。140 ms 是音频判定门槛，不是从人开口到扬声器停止的实测总延迟。
- 音频参考沿用板上 ES8311 → ES7210 MIC3 的硬件链路，不修改引脚或第三方组件。通过已有 codec 参数把物理 MIC3 的参考增益显式设为 0 dB，麦克风保持 30 dB；避免驱动默认把播放参考也放大 30 dB。依据 [微雪原理图](https://files.waveshare.com/wiki/ESP32-S3-AUDIO-Board/ESP32-S3-AUDIO-Board_1.1.pdf) 与 [ESP-SR AFE 输入定义](https://docs.espressif.com/projects/esp-sr/en/latest/esp32s3/audio_front_end/README.html)，`MR` 分别为麦克风和播放参考。后台使用能量门槛，并不识别声纹；实际回声抑制和插话质量需真机验证。
- HTTPS OTA 地址与已保存 WSS 地址的域名和端口完全相同时，附带已配对令牌；HTTP 和其他地址不附带令牌。远程配置与入口权限见 [REMOTE_ACCESS.md](REMOTE_ACCESS.md)。
- 支持固定电脑、固定手机与自动选择，切换先进入待机，确认目标后台身份后才提交 NVS 设置；失败恢复原策略。局域网名称失败时可使用配对后台的私人 IPv4 备用地址；保存策略后的开机不依赖电脑 OTA。详见 [BACKEND_SELECTION.md](BACKEND_SELECTION.md)。
- `/api/state` 的设备 `connection` 提供连接开始时间、待机确认状态及收到的二进制帧数，便于核对实际板端行为。本机 `POST /api/devices/:id/standby` 请求设备待机；返回 `requested: true` 仅表示请求已发送，实际确认需读取 `standbyConfirmed`。

## 构建与刷写边界

本机工具链为 ESP-IDF v6.1，提交 `fff9895c82d744c7237be8847347bdd1b07c6643`，Python 3.12。先安装并导出该工具链，再运行：

```powershell
. '你的 ESP-IDF 路径\export.ps1'
.\scripts\build-firmware.ps1
```

脚本校验上游提交并应用补丁，通过上游 `scripts/build.py` 构建 `waveshare/esp32-s3-audio-board` / `esp32-s3-audio-board`，仅输出应用镜像至忽略目录 `.runtime/firmware-repair/`，不会自动刷板。不要手动修改生成的 sdkconfig 或覆盖已有第三方组件。

该板当前分区：应用 ota_0 位于 `0x20000`，大小 `0x3f0000`；ota_1 位于 `0x410000`；assets 位于 `0x800000`。构建使用 `partitions/v2/16m.csv`，关闭资源刷写，保留板上 MultiNet7 中文资源和「你好豆梨」。对其他设备或更改过分区的板子必须重新读取并核对分区，不能直接套用这些地址。

刷写前读取完整 16 MB Flash 备份并校验 SHA-256；本地备份放在 `.data/device-backups/`，含私人配置。只写已经核对的应用分区，保留 bootloader、分区表、NVS、OTA 选择和 assets。需要回退时使用本次备份中对应的应用分区，不能用未知整片镜像覆盖。

### 2026-10-16 唤醒窗口根因与修订 8
