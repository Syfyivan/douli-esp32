核查日期：2026-10-25。交付目标是面向中国大陆成年用户、可通过私域邀请或官网注册使用的独立产品。本方案按完整交付范围组织，不按产品版本拆分。

## 产品边界与经营前提

产品定位：有稳定形象、声音、人设和可管理记忆的 AI 视频陪伴服务。核心使用路径是注册、了解 AI 身份与隐私规则、完成成年人资格核验、选择角色、开始通话、管理记忆、查看用量与订单。产品提供日常交流、情绪表达和生活分享；以健康使用、可靠体验和用户自主权为设计目标。

完整交付形态为电脑网页、手机 H5 和独立运营管理后台，共用账号和数据服务。网页包含完整注册、通话、支付和数据管理流程。移动浏览器和微信内置浏览器分别验收；不把浏览器模拟结果当作真机通过。若另行发行原生 App 或小程序，必须将对应客户端、平台审核和 APP 备案加入同一实际发行范围，不能把 H5 验收等同于全平台验收。

私域属于获客和分发方式。邀请码、微信群、付费社群、人数少、暂时免费，都不能单独证明服务不面向境内公众。开发者内部研发与招募外部客户持续使用需要分别判断。对本项目采用“对外服务”设计口径，不依赖“私域豁免”的假设。[生成式 AI 官方适用范围说明](https://www.cac.gov.cn/2023-07/13/c_1690898326863363.htm)

目前运营者尚无经营主体。推荐按中国大陆公司运营路径准备；是否能够采用其他主体，须依据属地登记、支付接入和业务许可要求判断。网络交易的零星小额登记例外有适用条件，涉及行政许可时不能直接套用；拟人化互动等服务义务也不随市场主体登记例外而消失。[现行网络交易监督管理办法，第八条](https://www.samr.gov.cn/cms_files/filemanager/1647978232/attach/20253/4cf5d392ec5e46db815ddc51a242be1f.pdf)

收费业务是否属于需要许可的增值电信业务，应提交实际产品、收费和数据流程给属地通信管理局核定。不能把“有收费”等同于所有情形都必须办 ICP 经营许可证，也不能把普通 ICP 备案当作经营许可。若落入增值电信许可范围，许可条件包括依法设立的公司。[互联网信息服务管理办法](https://www.samr.gov.cn/zw/zfxxgk/fdzdgknr/bgt/art/2023/art_483f0dd8eb1b4dc5961e4e008bd4a083.html)、[电信业务经营许可管理办法](https://www.miit.gov.cn/zwgk/zcwj/flfg/art/2020/art_ad4a7f072a5e4e2aab49b7817c49f5a6.html)

亲人定制包括经本人授权的在世成年亲人，以及通过专门权利审查的已故成年亲人纪念角色。原照片、历史原声与新生成内容分别标明；亲属关系不替代在世本人的授权，也不意味着继承死者人格权。角色默认私有，模型生成的话不能当作本人真实表态、遗愿或历史原话。向未成年人提供虚拟亲属服务属于现行规定明确禁止的情形，监护人同意也不能解除这项禁止。[民法典人格权编](https://www.cac.gov.cn/2020-06/01/c_15925617772683193.htm)、[拟人化服务规定第十四条](https://www.cac.gov.cn/2026-04/10/c_1777558395078289.htm)

## 用户关键流程

注册顺序：展示服务对象与 AI 身份 → 阅读协议及隐私说明 → 手机验证 → 年龄核验 → 必要紧急联系人信息与处理说明 → 角色选择 → 可选记忆设置 → 首次通话。

年龄判断不能只依靠“我已满 18 岁”复选框、手机验证码或模型猜测。接入可证明来源的身份/年龄核验服务，尽量只接收是否成年、核验时间及凭证编号；不自行长期保存身份证照片或完整证件号。具体数据必要性、服务可接入性和核验准确性须完成评估。提供非人脸核验或人工复核途径，避免把人脸识别作为默认唯一入口。

账号状态至少包括：待验证、成年人已核验、疑似未成年人待复核、未成年人保护受限、已停用、注销处理中。受限状态禁止陪聊、形象创建和充值，允许查看安全提示、联系监护人、申诉及处理历史退款；不把成人模式简单改名为未成年人模式。即使成年核验曾通过，遇到可信未成年线索也需复核，不能仅根据一句玩笑永久封禁。

未成年人保护模式、有效识别、申诉及保护措施的设计，需要按照实际业务与属地要求复核；“仅限成年人”声明不自动豁免这些义务。[拟人化互动服务规定，第十四条](https://www.cac.gov.cn/2026-04/10/c_1777558395078289.htm)

通话顺序：检查资格、权限和额度 → 明示计费口径及 AI 身份 → 申请麦克风 → 建立短期会话 → 收到可用媒体后进入通话 → 显示字幕/状态 → 挂断结算。等待连接、连接失败、服务端故障区间不计用户时长；供应商对此收费时由平台承担。摄像头、长期记忆及自定义形象分别授权。

退出支持按钮和明确的语音/文字意图；取消必须作用于正在连接及正在回复的状态。关闭浏览器、网络失联、进程崩溃时由服务端租约超时回收会话，防止无人连接仍持续产生费用。

## AI 标识与提示的实现

官网、注册页、角色页、视频画面、字幕区域和记录导出均有适合场景的 AI 提示。视频采用首屏提示加持续可见的“AI 生成形象”标识；全屏、窄屏和画中画分别验证。纯音频模式以开场语音说明 AI 身份。标识不能只放在用户很少打开的协议里。

下载或分享的文本、音频、图片、视频，按格式保留显式标识及要求的文件元数据；水印、元数据和数据库审计是不同层次，互不替代。为每个内容生成不可逆推出个人身份的内容编号，关联服务商编码和生成属性。第三方返回的标识经转码、封装和导出后还需检查；本产品不提供无标识导出选项。[标识办法](https://www.cac.gov.cn/2025-03/14/c_1743654684782215.htm)、[现行强制国标 GB 45438-2025](https://openstd.samr.gov.cn/bzgk/std/newGbInfo?hcno=F32EA2A561F1886CD8D606513512D547)

生产前以实际文件格式和媒体播放方式核对国标实施细节，不把一个 HTML 角标当作整个媒体链路完成标识的证据。协议文本中说明标识形式及传播义务。

使用提醒由服务端累计，跨刷新和短暂重连延续。本产品主动每 60 分钟温和提醒；同时落实连续使用每超过 2 小时的提醒要求。过度依赖风险触发独立提示，不等到固定计时点；提醒不强迫消费或放弃未用余额。[拟人化互动服务官方干预说明](https://www.cac.gov.cn/2026-04/10/c_1777558395284407.htm)

| 对话模型 | 使用具有相应备案信息、允许该陪伴场景的境内商用 API；逐一核对具体模型、版本、合同主体和处理地域 |
| ASR/TTS | 复用现有语音适配能力，并新增专属音色创建、查询、试听、合成及删除；核对亲属/已故人物复刻场景授权、并发额度、数据保留和故障策略 |

## 技术架构与项目拆分

采用独立仓库和模块化服务。沿用 React 与 Node.js/Fastify 的主要技术路线；以明确模块边界实现完整产品，避免在用户量和团队规模未明确时增加无必要的分布式系统。

    电脑网页 / 手机 H5
          │ HTTPS / WSS，短期媒体凭证
          ▼
    应用 API：账号、同意、资格、角色、记忆、订单、投诉
          │
    实时会话服务：轮次、ASR、回复审核、TTS、数字人、取消、用量
          │
    境内模型 / 语音 / 数字人 / RTC

    PostgreSQL：持久业务与支付账本、同意证据、记忆、审计
    Redis：限流、短期会话租约、并发占位、缓存
    境内对象存储：授权素材、用户主动导出、隔离审查附件
    后台任务：记忆整理、删除、退款对账、通知、供应商会话回收
    管理后台：独立身份域、岗位权限、多因素认证、审计

建议目录：apps/web、apps/admin、services/api、services/realtime、workers、packages/contracts、packages/conversation、packages/providers、packages/policy、infra、docs。它们可以在同一仓库中独立启动及部署；是否拆成多个进程由实时会话扩容需求决定。

现有个人数据库不直接作为新产品数据库。迁移工具支持运营者自行选择导入自己的记录；默认不迁移 API 密钥、配对凭证、其他家庭成员资料和本地音频。导入有来源、范围、回滚和验证报告。

## 会话、审核与计费的关键实现

实时状态至少包含：资格检查、准备、连接、监听、生成、播放、暂停、重连、结束。每轮有 callId、turnId 和 cancellation epoch；所有迟到音频、字幕和记忆任务验证归属及轮次。重连生成新的短期凭证，不能复用失效 token。

输入先做风险分析；输出采用足够上下文的短句缓冲，经审核后才送入 TTS 和数字人，避免先播违法内容再补拦截。后台结合整段会话识别依赖和极端情境。审核失败或服务不可用时暂停相应生成，提供明确提示并停止相关计费；不把不确定判定直接当作永久封禁依据。

用量与账本由服务端维护。开通前校验可用额度、预留并发及短期额度，结束时结算，多余预留释放。支付订单、回调、退款、额度变动有幂等键；Redis 不是唯一财务依据。用上游会话状态与服务端时间校验客户端心跳，杜绝伪造前端时长获利。明确区分计费时长、模型生成时长和用户实际听到的内容，不能伪造精确已播放证明。

通话中用户保持静默但会话有效的计费方式必须提前展示；后台超时、故障和主动暂停规则清楚区分。重连不能重复扣费；额度用尽先提醒再按明确规则结束，避免静默转成高价计费。

## 隐私、数据与删除策略

本产品不将日常聊天或上传素材用于通用模型训练、公共音色库及其他用户的角色。用户专门上传并完成合法授权的照片和声音，可在单独说明及相应同意范围内用于创建该私有角色所必需的音色特征提取、专属模型训练或适配；不能笼统写成“任何数据都不用于训练”后实际训练音色。此用途与实时推理、内容审核、记忆整理分别告知；供应商须同样遵守用途限制，不得自行用于通用模型改进。

处理敏感信息、委托处理及其他高风险用途须做个人信息保护影响评估，确定必要性和最小范围；同意不可替代必要性。数据权利入口与账号注销同时交付，建立定期合规审计。[个人信息保护法](https://www.cac.gov.cn/2021-08/20/c_1631050028355286.htm)、[合规审计管理办法](https://www.cac.gov.cn/2025-02/14/c_1741233507681519.htm)

删除状态为“已提交、处理中、业务数据已清理、备份待轮转、完成/依法保留说明”，不笼统承诺所有介质即时清零。记忆删除需处理来源、摘要和向量，否则可被后台重新提取。安全证据依法保留期间与普通推荐和模型上下文隔离。

## 安全运营与人工处置

建立岗位而不仅是审核开关：运营负责人、技术安全负责人、隐私负责人、内容审核/客服、紧急事件值守及财务；可以由少量人员兼岗，但退款、敏感数据导出等关键操作应有复核。

风险流转：检测到异常 → 采用经审核的支持性回应并给出求助入口 → 必要时暂停角色化互动和付费引导 → 进入高优先级人工队列 → 按风险程度及法定要求联系紧急联系人或相关援助 → 记录处置 → 复盘和申诉。普通低落与明确生命危险应区分；风险模型不能承担临床诊断。

对明确自伤自杀或重大财产损失等极端情境，要落实必要援助和及时联系，而不是只写“后果自负”。联系人失效、本人未确认、无法接通等情况有替代处置预案。人工流程不应导致法定及时干预被无限延后；紧急披露仅限必要信息，避免将完整私聊转发给联系人。具体值守覆盖必须与开放服务时段相匹配。[官方干预义务说明](https://www.cac.gov.cn/2026-04/10/c_1777558395284407.htm)

针对老年用户提供易读提示、防诈骗与异常消费复核及人工求助。投诉分为一般服务、消费、隐私、身份误判、素材侵权和生命安全，分别处理；普通工单拟定 1 个工作日确认受理、7 个工作日内给出处理进展，复杂情况解释原因；法定更短期限和紧急事件优先适用。

本产品不建立用户公开角色交易市场或用户间私聊；官方角色目录和个人私有角色足以构成完整陪伴产品，减少与核心目标无关的传播、交易和陌生人社交业务。自定义角色仍需审核、授权证明和撤销机制。
