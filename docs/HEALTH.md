# 个人健康档案与医学依据

适用于整理自己的症状、检查报告和用药问题。入口是「我的健康」；普通聊天或 ESP32 被路由到健康场景时，也使用相同服务。回答提供解释、待补充信息和就医提示，不作确诊或个人处方调整。

## 使用

1. 在「健康档案」填写自己确认的既往疾病、过敏、背景和当前用药。药品尽量填写通用名、全部活性成分、剂型、规格、实际用量和频率；不能凭商品名猜成分。
2. 「检查报告」支持 JPG、PNG、WebP、PDF，单份最多 10MB、PDF 最多 12 页。上传先保存到本机；点击「发送给模型并识别」后，文件或 PDF 页面会发送给配置的模型服务商。默认识别模型使用日常模型，也可单独配置支持图片的模型。
3. 识别结果只是草稿。对照原件核对日期、数值、单位、参考区间和标本后确认；尚未看清的项目不能确认。只有已确认报告进入问答和趋势。
4. 趋势按项目名称、单位和标本分组，不换算单位，也不把“<2”“阴性”等结果强行变成数字。每次保留自己的参考区间和机构；同组不保证不同实验室、方法的数值可直接比较。
5. 「健康问答」可选最多五份报告，并连续追问。ESP32 读短回答，手机/电脑展示解释、问题、证据和引用核查状态。

## 资料库

公共医学资料和个人档案分开。采用按需检索、短期缓存、版本化资料导入，不批量下载商业医学书籍。

| 来源 | 实际获取内容 | 限制 |
| --- | --- | --- |
| [MedlinePlus.gov Web Service](https://medlineplus.gov/about/developers/webservices/) | 英文健康主题摘要 | 一般健康解释；接口不提供的发布日期不猜测 |
| [PubMed / NCBI](https://www.ncbi.nlm.nih.gov/home/develop/api/) | 相关论文摘要、期刊及日期 | 摘要不是全文；单项研究不等于临床建议，剔除标为撤稿的条目 |
| [DailyMed](https://dailymed.nlm.nih.gov/dailymed/app-support-web-services.cfm) | 美国具体制剂说明书的相关章节 | 通用名检索得到候选，必须核对厂家、剂型、规格、成分及适用地区 |
| 中文权威网站 | 限定卫健委、药监局、默沙东等域名的搜索摘要 | 复用全局 DeepSeek/Brave/必应搜索配置；明确标示未核对全文 |
| 用户导入资料 | 有权保存使用的原文 | 必填来源、机构、地区、版本、发布日期、复核日期和授权依据；可停用旧版 |

联网结果缓存 24 小时，页面显示来源覆盖范围、检索时间、地区和失败状态。导入资料的停用和复核状态不会被旧缓存覆盖。模型引用必须匹配本次实际检索到的原文短句；未匹配的引用会被剔除并提示。匹配原文不代表结论或人群适用性已经获得临床认证。

当前可直接使用免费的 MedlinePlus、PubMed、DailyMed 接口。中文在线检索复用[联网搜索配置](WEB_SEARCH.md)，关闭或服务不可用时会显示真实状态；仍可导入有权使用的国内资料。这里集成的是资料接口和工作流程，不依赖把研究类 Agent skill 当作诊断工具。

## 保存、模型与隐私

个人健康档案、原件、识别结果、医学对话和证据缓存保存在独立表，使用本机密钥 AES-256-GCM 加密。普通聊天表只留健康对话引用与占位文本，读取界面时从健康档案还原；自动普通记忆提取不处理这些健康对话，识别更正也不能写回普通明文消息表。

这不是全离线模型：提问和所选已确认档案会发给用户配置的回答模型；识别会发给图片模型。外部检索接口只接收通用医学主题、检查名或明确药品名，不接收原始报告。检索主题由模型生成，并有显式身份格式过滤；不能保证自由文本中的任意身份信息都能被自动识别。

导出 JSON 为明文，由用户选择保存位置。同步给已配对设备时，传输整体加密，落地使用各自的本机密钥重新加密。请保管设备与备份中的 `local.key`，丢失密钥无法恢复档案。
