# 本地生活记录

## 存储与使用

继续使用服务所在电脑的 SQLite，不新增云端数据库。源码运行默认 `.data/douli.sqlite`；Windows 安装版默认 `%APPDATA%/Douli/data/douli.sqlite`，以实际后台的数据目录为准。额外个人档案沿用 `people/<id>/` 独立数据库。模型整理仍会调用用户配置的外部模型，本地存储不等于离线推理。

入口为「我的资料 → 生活记录」。原「近期经历」改名，原有「按天或对话回顾」入口继续保留。

- 按发生日期、主题、经历/计划和关键词组合筛选，分页查看。
- 「记一件事」可以补充生活记录，无需调用模型。手动记录的最初原话保存为独立会话，来源显示「手动生活记录」。按天/对话回顾由本地后台根据已保存条目重建，关闭自动提取后仍可使用，刷新可能稍有延迟。
- 主题可多选：日常、工作、学习、社交、家庭、睡眠、饮食、运动、心情。未知分类不保存；升级前的记录显示「未分类」，可以手动补选。升级不会批量调用模型重做旧记录。
- 「修订记录」修改整理后的内容、发生/结束日期、类型与主题，不改写聊天原话。仅改内容或主题时，界面保留原有具体时分秒。打开旧表单后如果记录已变化，保存返回冲突，用户重新打开再处理。
- 「移除记录」让条目退出生活记录、经历检索、摘要和向量索引；保留最初聊天原话及来源关联。要删除原话，请在聊天记录中另外操作。移除不等于删除所有原始资料。
- 自动整理、手动记录和已手动修订分别标注。计划不会因日期过去而自动变成已完成经历，一次事件也不会自动变成稳定偏好。

健康档案、报告和健康问答继续使用现有独立加密流程，不复制到普通生活记录；已标记为健康私密的对话仍排除出普通自动整理。生活主题不提供医学判断，也不能保证自动识别任意自由文本中的敏感信息。普通生活记录与聊天沿用现有本地存储方式，不是全库加密。

## 数据结构与维护规则

复用 `memory_episodes`，在事务迁移中追加：

| 字段 | 作用 | 旧记录默认值 |
| --- | --- | --- |
| topics | 允许列表中的主题键，JSON 数组 | `[]` |
| origin | `automatic` / `manual` / `edited` | `automatic` |
| revision | 编辑版本，防止旧表单覆盖新数据 | `1` |
| deleted | 是否已从生活记录中移除 | `0` |

原有发生时间、记录时间、经历/计划类型与逐字来源继续保留。删除标记保留原记录 ID 和来源，清空整理正文及主题，防止后台再次生成同一原话的经历。查询、向量索引和摘要均排除该标记。更改记录时同步清理相关摘要与向量，再由原有队列重建受影响的回顾。

**人工维护优先的范围是整段来源原话。** 一旦其中一条经历被人工修订或移除，该原话的经历不再被后台重新提取覆盖；已存在的其他条目保留，事实建议提取仍独立进行。这个取舍避免模型换一种措辞生成重复记录。若之后更正或删除来源原话，沿用既有依赖失效机制，相关整理记录（包括人工修订）失效，新的原话可以重新整理。人工修订不作为独立于来源的永久副本。

手动新增的原话带 `diaryEntry` 和 `memoryOperation` 标记，防止作为普通聊天再次提取稳定事实；它的经历条目可照常参与经历查询。

现有多设备同步会携带新增字段，并在接收记录时递增本地编辑版本。两端必须升级到相同结构；旧客户端会收到结构不一致提示。同步仍采用现有冲突决策，不提供字段级合并，也没有改造为云端托管。

## 接口与验证

- `GET /api/memory/diary`：`q/from/to/topic/kind/limit/offset`，`from` 含起点、`to` 不含终点；界面的结束日期转换为次日边界。
- `POST /api/memory/diary`：`text/kind/occurredAt/endedAt/topics`。
- `PUT /api/memory/diary/:id`：相同字段加必填 `revision`。
- `DELETE /api/memory/diary/:id`：请求体 `{ "revision": 1 }`，移除记录。
- 原 `/api/memory/episodes/:id/sources` 继续提供原话；已移除记录返回 404。

接口沿用个人档案作用域，未知档案、记录不存在和旧版本冲突分别拒绝处理。主题和日期在服务端校验，模型自动分类仅保留允许值；所有验证先于创建原始会话，避免无效请求留下半条记录。
