## 2026-10-20 告别后结束会话

修复“回答了拜拜但仍保持唤醒”的问题。完整告别口令现在允许“嗯、好的、谢谢”等口语成分；例如“嗯，好的，再见豆梨”直接进入待机，不等待回答模型。引用、否定、提问或附带其他要求不会因包含“再见”被本地规则截断。

其他表达由日常模型单独判断是否结束本次聊天，只返回布尔 JSON。判断只发送最新转写及助手名称，不发送历史或个人资料，与原有回答和语音合成并行；每个非本地指令的语音轮次增加一次短模型请求，最多等待 2.5 秒。不能把回答中的“再见”当作控制指令。接口失败、超时或无效输出不会猜测关机，明确口令仍可用。

语义判断确认结束后，服务端在本轮语音发送完成后发出 `session/standby`；回答或合成失败也不撤销已确认的结束意图。沿用板端待机确认和 5 秒未确认断连兜底；待机期间拒绝音频，下次唤醒创建新会话。旧轮次被打断后，迟到判断不能结束新一轮。未知声纹同样适用，且仍不读取或保存任何个人记忆、历史或音频。

真实日常模型的 21 条文本样例通过，包括“回头再聊”“你休息吧”“不用再陪我说话了”“有事再叫你”，以及否定、改口、引用、翻译、继续提问等反例。语义请求本次约 0.50–1.93 秒，明确口令本地完成；该时间不是扬声器端到端延迟，也不代表所有说法的识别率。板端真实人声效果需另行复测。

相关回归覆盖本地告别、语义结束、已识别／未知身份、合成与回答失败、迟到判断隔离、首段语音不等待判断、待机确认及下次唤醒的新会话。独立后台服务启动后，已在另一个 shell 确认健康接口正常、板子在线并确认待机；这项重连检查不等同于真人告别验收。

## 2026-10-20 语音回复延迟优化

- 现场设备与主机通过同一局域网的 WebSocket 直连，心跳约 4–8ms。这个数字只代表设备链路，模型和语音合成仍调用云端服务。
- 硅基流动 PCM 合成请求显式传入 `stream: true`；其他兼容提供商不添加此供应商字段。参数依据[硅基流动语音合成接口](https://docs.siliconflow.cn/docs/api/audio-speech-post)。
- 回复按短句合成。下载达到 800ms 音频储备、且从首字节起的平均交付速度至少为播放速度的 1.25 倍时，允许边收边播；不足储备的短句完成后立即播放。首次达到储备时已经偏慢，则等待该短句下载完成，避免已知慢速来源造成断续。后续突发网络停顿仍可能影响播放，这不是无卡顿保证。
- 下载与按节奏发送音频分开；最多一个合成请求在途、一个后续短句预取，单段 PCM 上限 4MiB。继续保留打断取消、重采样和设备发送节奏。回复诊断增加各阶段计时，访客模式仍不保存个人记忆或对话正文。
- 真实云端合成探测中，同一固定文本开启流式参数时一次 4.52 秒收完、关闭时 12.22 秒；但开启后复测也出现 21.53 秒。连接诊断确认该接口当时经过美国代理出口，因此不能把单次差异视为稳定收益。探测只记录时间和音频长度，没有保存音频，也没有播放到板子。
- 本轮 60 项相关测试通过，覆盖快慢音频源、完整帧数、取消、短句预取、访客隐私与原有语音流程。这些是代码与模拟协议验证，实际说话到板子开口的延迟仍需真人测量。

## 2026-10-20 欢迎语被误打断

现场记录显示：欢迎语命中缓存，2ms 开始发音频，最大帧发送间隔 33ms；缓存音长 2.12 秒，但仅发送了 1.46 秒音频，就被服务端的打断判定截断。用户反馈保持安静也会出现。这个记录证明本次截断来自打断路径，结合静默复现推测是残余回声；没有把设备声明支持 AEC 当作回声已经消除的证明。

ESP32 默认的意图打断模式现在要求识别内容与正在发送的播报不同，或识别出明确打断请求；不再仅凭累计 600ms 人声停止播报。与最近已开始发送的段落相同的转写片段按疑似回声处理，等待识别期间继续播放。后续新说话保留并重新识别，候选音频最多保留 6 秒。立即打断模式仍保留原语义。诊断只记录判断原因和计时，不新增保存语音或转写正文。

68 项相关测试通过，覆盖缓存欢迎语完整发送、回声片段、真实插话、识别等待期间继续说话、缓冲上限及原有语音流程。这是文本和状态层面的保护，不替代设备声学回声消除；真实扬声器效果需要再验证。

## 真实服务检查与待验收项目

现有硅基流动配置已做一次不落盘的合成语音回环：固定测试句「你好豆梨，这是语音连接测试。」经 CosyVoice2 返回 142 个网络块，首块 1943ms、完成 2194ms，合成音长 3.6 秒；Qwen3-ASR 返回「你好，豆梨，这是语音连接测试。」，得到 4 次预览，输入结束后 223ms 得到最终结果。该结果证明这次真实接口分块和转写链路可用，不代表真人识别率、扬声器回声或用户实际端到端延迟。

随后用同一句合成语音检查实际 WASM 人声检测路径：132 个 20ms 帧中 92 帧判定为人声，转写仍正确。第二次接口首块 3929ms、完成 4085ms，说明单次速度不能代替延迟分布；音频仍未保存。

后续复用了本机已经配置的 `Qwen/Qwen3.5-35B-A3B` 图片模型，为新的「画面理解」配置保存同一服务地址、模型和密钥；现有报告识别配置与默认通话模式保持原值。以自制测试卡验证真实视觉服务，5120ms 返回正确数字 4729、左红右蓝及圆形；其中 200×180 的红色矩形被描述为正方形，表明几何细节仍可能误识别，不能把单张测试视为模型质量验收。

另在隔离数据库运行完整画面问答链路：本地 WebSocket 提问 → 服务端请求本轮画面 → 真实视觉模型 → 真实日常模型 → 真实合成音频。只请求一帧、回答包含 4729、确实收到非空 PCM，数据库消息与元数据中没有图像内容；测试结束后隔离服务已关闭。这是自制图片的真实接口集成验证，没有采集手机屏幕、摄像头或实际播放到扬声器。测试结果保存于忽略目录 `.runtime/voice-vision-call-result.json`。

## 可选服务配置与边界

- 默认「现有模型组合」不变。火山流式识别在「输入」选择该服务，在模型页配置 `https://openspeech.bytedance.com/api/v3/sauc/bigmodel`、已开通资源 ID（例如 `volc.seedasr.sauc.duration`）及 API Key。
- 「火山原生全双工」使用 `https://openspeech.bytedance.com/api/v3/duplex/realtime/dialogue`、模型 `1.2.6.1`、已开通 API Key，默认音色 `zh_female_vv_jupiter_bigtts`。日常模型和兼容 TTS 仍用于需要本地引擎处理的场景。开始下一次通话后生效。
- 原生模型接收持续音频，由云端判停和打断。级联模式的人声检测／短附和策略不替代云端判停。输入与输出都设有有界缓冲；上行拥堵或长时间暂停造成积压时明确结束并提示，避免无界占用。
- 原生输出会等待本地路由与前置操作；记忆、工具和存储共用现有引擎。会话初始提供近期可用上下文，每轮刷新系统提示和记忆数据；云端更新影响当前生成的具体时机仍待真实服务核对。
- 原生接口未提供文字与音频的精确逐字对齐，因此把一次原生回复作为一个保守播放段。中途打断不会猜测已听到的字数；本地与回写云端的上下文使用已确认播出内容。健康、记忆操作和设置操作不会回写普通云端历史。
- 画面只在明确分享后、本轮提问时发送一帧给所配置视觉服务；没有持续视频分析，原图不写入数据库或音频归档。

## 2026-10-21 首句、停顿与双向语音合成

普通停顿默认改为 500ms；本机原配置为 650ms，已同步更新。关闭额外云端结束判断，保留本地自适应判断：「因为。」「我想。」「让我想想」「我还没说完」等未完成表达仍等待至少 2200ms。实际麦克风断句体验尚待真人验证，规则测试不能证明所有犹豫和改口都能识别。

兼容 TTS 的首段分段计时由 650ms 调到 350ms。计时到点时文字太短，后续文字达到输出长度即送合成，不重复等一个计时周期；已有自然标点仍立即分段。该时间是本地分段等待，不包括模型尚未生成足够文字的时间。语音提示词要求首句简短、直接回答，不用占位话拖延。

增加可选「豆包双向流式合成 2.0」。在模型页填写资源 `seed-tts-2.0`、对应 API Key 和官方音色（预设 `zh_female_vv_uranus_bigtts`），先试听，再在输入设置切换语音合成服务。级联聊天整轮持续发送模型文字增量、接收 PCM；一条 WebSocket 顺序复用多个会话，空闲 30 秒关闭。打断取消旧会话、丢弃旧音频。连续合成达到 800ms 音频储备即可播放，等待模型文字的间隔不再触发「整段下载完成再播」；兼容 HTTP 合成继续保留原有慢源防卡顿策略。两条链路都限制积压及单轮总量。

协议依据：[火山双向流式 v3](https://docs.volcengine.com/docs/DoubaoVoice/WebSocketBidirectionalStreaming-V3?lang=zh)。开通前，本机已有火山 Key 的真实握手返回 HTTP 403，资源未授权；新版试听接口也返回明确的未开通提示。当时仅准备未启用的豆包配置，保留 CosyVoice2。随后用户明确授权开通，实际接入结果见下文。
