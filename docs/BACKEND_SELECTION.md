# ESP32 后台切换

在「设备与家居 → 我的 ESP32 → 板子连接哪个后台」中选择「固定电脑」「固定手机」或「自动选择」，点击「应用连接方式」。若侧栏没有设备入口，在「设置 → 功能显示」开启「设备与家居」。页面分别显示当前实际连接的后台、已生效的方式和切换结果。

- 固定电脑：连接电脑后台。固件 2.5.2.11 起优先使用同网直连，局域网不可达时使用已配置的加密公网入口。
- 固定手机：连接手机豆梨服务，手机与板子需在同一局域网，手机服务必须运行。
- 自动选择：新建连接时先尝试电脑，失败后尝试手机；健康连接不会被强行迁移。电脑恢复后，不打断正在使用的手机连接，下次重连重新优先电脑。

两端先通过现有同步功能配对，完成模型设置及 ESP32 授权同步。这个配对同时同步聊天、记忆、健康档案和设置，详见 [SYNC.md](SYNC.md)。管理页面只能选择已配对且可访问、设备令牌一致的后台，不能填写任意服务器地址。

切换会立即结束当前对话并进入待机。板子先保存试用配置，收到目标后台的身份确认后才提交新设置；目标连接失败时恢复原设置。断电发生在确认之前也恢复原设置。固定模式一旦生效，之后目标离线会持续重试该目标；需要自动接手时请选择自动模式。

后台切换不等于切换 Wi-Fi。板子的 Wi-Fi 配置保留，手机也不会自动成为公网服务。电脑和手机之间的同步、控制转发目前依赖局域网；已有电脑公网入口只开放设备协议，不开放管理与同步接口。电脑后台启动期间，可以从电脑页面控制已连接手机的板子，前提是电脑能访问配对手机的同步服务。

## 地址与保存

配对后台各有独立的 `douli-node-<节点 ID 前八位>.local` 名称，避免固定模式受共享名称的主机优先级影响。对于局域网目标，同时保存切换时确认的私人 IPv4 地址作为名称解析/连接失败后的备用地址。备用连接也必须通过后台节点身份校验。路由器隔离、组播限制或地址变化可能导致两种地址都无法到达，此时恢复网络后重新应用设置。

支持 `hello.features.local_backend_priority: true` 的固件收到电脑策略时，按本地名称、保存的私人 IPv4、加密公网 `remoteUrl` 的顺序尝试连接；三条路径使用同一已配对后台身份及令牌。公网备用只允许 WSS。旧固件仍收到原来的公网优先策略，避免发出其无法理解的备用配置。升级后重新应用连接方式即可保存新策略；正在使用的健康连接不会因网络变化被强行切断。

从公网切到局域网时，新连接可能先于旧连接的确认消息到达。后台只在同一已授权设备的新连接明确报告同 revision 已生效时确认切换，不能仅凭断线或重连判定成功。

固件 2.5.2.3 声明 `hello.features.backend_selection: 1`。后台以 `backend/configure` 发送含 revision 的策略，板端 `ack` 只表示接受；只有同 revision 的 `backend/status` 报告 `phase: applied` 才显示已生效。`failedRevision` 用于明确报告回退。两分钟未确认时页面显示未确认，不能当作成功。

策略与令牌仅写入板端 NVS `douli_route.state`；管理 API 不返回令牌或完整连接策略。旧 `websocket` / `wifi` / `ota` 配置保留。已确认策略的开机连接不依赖电脑 OTA 服务，因此自动模式和固定手机模式可在电脑后台关闭时启动。

管理 API 为本机 `GET/POST /api/devices/:id/backend`，POST 仅接受 `mode`。跨后台转发复用已配对的加密同步通道，设备端口和公网入口不开放这条管理路由。

## 验证范围

`tests/backend-selection.test.mjs` 用真实本机 HTTP/WebSocket 和模拟板子验证请求转发、确认/回退状态、目标授权及凭据不外泄；不能当作硬件验收。`scripts/check-firmware-backend.ps1` 编译实际固件状态机，使用替代 NVS 检查提交、写入失败、断电恢复、自动轮换和固定模式重试。目标板编译与真机记录见 [FIRMWARE.md](FIRMWARE.md)。
