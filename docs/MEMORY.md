# 豆梨记忆系统：按轮增量整理

记忆保存在服务所在设备的 SQLite 中。升级采用事务内增量迁移，原偏好、记忆状态、聊天和设备配对保持兼容。向量和摘要也是本地数据；生成它们需要调用已配置的模型服务。不要将 `.data`、`.runtime` 或包含用户内容的测试报告提交到 Git。

## 五项能力

1. **混合检索**：中文分词/BM25 与向量相似度联合召回，可用独立重排模型筛选相关性。过滤未确认、已过期和尚未生效的事实；固定资料与普通检索分开分配预算。模型或网络不可用时降级为关键词检索并显示状态。更换向量模型会使旧索引失效，后台逐批重建。
2. **经历与历史查询**：每轮完整回复结束后，后台整理本轮用户发言和助手回答，同时提供少量前文与相关旧记忆。稳定事实与带日期的经历/计划分别保存，助手回复只用于理解语境，不能成为用户事实的证据。经历按发生时间查找，原始聊天按发言时间查找；例如今天说“昨天吃了火锅”，经历属于昨天，原话属于今天。支持昨天、上周、上月及 ISO 时间范围，可展开逐字证据并打开原对话。
3. **结构化事实**：每条记忆包含人物、具体属性、属性值、类型、生效/失效时间和多条原话证据。`food:香菜` 与 `food:面条` 是独立属性；同一属性的新值需要确认替换。修改内容保留历史版本，模型可通过 `memory_search(query, at)` 查询指定时间成立的事实。
4. **语音记忆操作**：文字和语音共用相同流程。明确提出记住、更正或忘记后，先读出具体内容，再用“确认”或“取消”完成。确认仅限当前会话，五分钟到期；相关原话或记忆被其他会话修改后，旧确认失效。操作会作为结构化结果传给界面，回复也经过现有语音合成链路。
5. **后台整理**：持久化队列支持失败重试，只整理新增或受更正影响的对话。模型判断新增、补充、变化和到期；影响事实内容或有效期的变化仍需确认。等价事实补充来源，同人物、同属性的重复表述分批比较合并，保留历史记录和证据。到期状态自动归档；已确认稳定资料与按问题检索的其他事实、经历分别分配上下文预算。

## 增量处理与来源

自动整理没有“每条用户消息最多三条事实”的固定限制。长发言分段提取，所有段通过后才一起保存；一个批次最多处理三轮任务，这个吞吐限制不是记忆条数限制。没有有价值的新信息时可以输出空结果；非空输出全部未通过证据校验时保留失败任务重试。

每轮输入包含本轮用户/助手消息、最多十二条且受预算限制的前文，以及按相关性选出的旧记忆。事实和经历都必须引用本轮用户逐字原话；消解指代需要的额外证据也必须来自用户。保存相关消息的内容指纹，整理过程中原话或旧记忆变化会使该次结果失效。原话更正后，相关事实进入待复核，经历及摘要失效，并重新排队；删除或遗忘会清除相关经历、来源和衍生索引。健康私密对话、助手设置指令和记忆管理指令不进入普通自动整理。

经历单独保存在 `memory_episodes`，包含发生时间、结束时间、记录时间、经历/计划类型和原话来源。每日/会话回顾由受影响的经历重新分组，不再每分钟将所有聊天发给模型重写摘要。已有聊天仅在升级时排队补充经历，原有事实确认状态保持不变。此补充会按现有经历设置调用已配置的记忆模型。

回答前，称呼、居住地、职业、固定资料及手动偏好占用有限的核心预算；其他内容按问题相关性检索。询问“昨天做了什么”优先按发生日期取经历，询问“有什么忌口”按属性及语义查偏好。不会因为一份旧摘要很近就无条件加入回答。历史模型仍可能误解语义，证据校验不能证明抽取内容必然正确。

## 使用

- “记住，我不吃香菜。” → 豆梨复述 → “确认”。
- “更正记忆，我现在住上海。” → 豆梨说明替换 → “确认”。
- “忘掉关于香菜的饮食偏好。” → 核对内容 → “确认”。
- “昨天聊过什么？”或“上周提到的出差是哪天？” → 查询原话；找不到应明确说明。
- “取消”撤销当前操作；其他话题会取消原待确认操作，防止后续一句“好”误改记忆。

“偏好与记忆”页面提供语义查找、历史查询、结构化编辑、原话证据、过去版本、每日/会话摘要以及后台进度。手动填写的明确偏好仍独立于自动提取的事实。

忘记操作会删除对应事实、清理相关摘要/向量，并将对应原话及可追溯的衍生回答排除出后续记忆查询。原始聊天仍可在聊天记录中查看或单独删除。抑制记录只保存指纹；明确再次要求记住该属性可以恢复后续提取。无法将这种规则声称为对所有语义改写的完美阻止。

## 模型与设置

- `models.memory`：每轮事实/经历提取、等价判断和纯语义候选的相关性核验；留空沿用日常模型。可使用独立模型，减少与日常回复争用。相关性核验超时或返回无效结果时，仅保留关键词匹配，并在页面显示降级状态；历史原话会逐条核验，避免一份多话题摘要带入整段无关对话。
- `models.embedding`：兼容 `/embeddings` 的向量服务。
- `models.rerank`：兼容 `/rerank` 的相关性重排服务。
- 开启语义检索、且向量/重排留空时，若日常模型使用 `https://api.siliconflow.cn/v1`（或 `.com`），会复用同一账号的 `BAAI/bge-m3` 和 `BAAI/bge-reranker-v2-m3`。其他服务商需明确配置，不能假定聊天模型支持生成向量。
- `memory.contextTokens`、`memory.historyTokens`：保守估算的上下文预算，默认 2400 / 5000；不是服务商返回的精确 tokenizer 计数。当前用户消息单独保留。
- `memory.minSimilarity`、`memory.minRelevance`：候选召回与重排阈值，默认 0.42 / 0.01。不同模型分数不可直接类比，应结合自己的样例调整。
- `memory.semantic`、`memory.autoSummaries`、`memory.maintenance`：分别控制语义检索、经历及回顾生成、后台合并和到期整理。关闭生成不删除已有内容。
- `privacy.autoMemory`：控制普通聊天生成事实建议。用户主动提出记住、更正、忘记仍可使用。

默认每分钟后台处理一次，完整回复结束后也会触发小批量处理。每批最多处理 3 轮提取任务、3 组受影响的回顾和 64 条向量；合并按发生变化的属性分组并分页处理。失败提取按递增间隔重试，五次后在页面显示待重试，点击“整理并更新索引”可重试。原始聊天始终保留。

## 验证与边界

自动化检查：`npm test`、`npm run build`。新增测试覆盖旧数据库迁移、检索降级、模型更换后的索引失效、属性和时间范围、证据更正/删除、确认会话隔离与过期、历史工具、音频入口到确认和播放、后台整理及预算。

增量整理检查：`node scripts/check-memory-incremental.mjs` 独立启动后台进程，在 `.runtime` 中创建隔离数据库，读取本机现有模型配置测试虚构对话。使用 `node scripts/check-memory-incremental.mjs --verify` 查看完成结果及独立健康检查；通过后临时页面保留十分钟用于界面检查。报告和模型原始输出均仅保存在该隔离目录，不修改用户数据库。脚本检查多条事实、否定、人物关系、昨日经历、确认变更后保留历史、HTTP 来源查询和重新打开数据库后的召回。

`node scripts/check-memory-v2.mjs` 使用本机已配置的真实服务，在 `.runtime` 下创建隔离数据库，验证语义检索、事实提取、摘要、跨会话记忆、修正/删除和合成语音往返。测试不会向用户数据库加入虚构资料；报告写入 `.runtime/memory-v2-live-check.json`。若尚未配置记忆模型，硅基流动环境的检查脚本用独立 `Qwen/Qwen3.5-4B`，部署时需让实际配置与验收配置一致。

所有模型生成的事实都可能误解原话，自动提取仍需确认。后台摘要是可追溯的对话概括，不是永久偏好。软件、模拟设备和合成语音的通过不代表真人识别率、ESP32 硬件、模型整体质量、跨日陪伴效果或其他平台已经验收。
