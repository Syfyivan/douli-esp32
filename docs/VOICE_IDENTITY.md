# 豆包识别与家庭成员

设置 → 声音与语音可选择豆包 ASR 2.0 双向流式二遍接口。推荐地址为 `https://openspeech.bytedance.com/api/v3/sauc/bigmodel_async`，资源 ID 为 `volc.seedasr.sauc.duration`。密钥只填入应用设置，由本机密钥加密保存。

正确的助手名字、已确认词典词条作为热词发送；近期非敏感对话作为语境。只发送正确拼写，不把“老李”等误识别词加入热词。语音中的独立问候及直接称呼会按设置修正，如“再见，老李。”→“再见，豆梨。”；“我朋友老李今天来”、引述和文字输入不套用这条称呼修正。修正前的原文保留供查看。旧的助手称呼词典在迁移时改为仅限语音直接称呼。

## 两人使用

1. 设置 → 家庭成员与声纹，分别创建个人档案；侧栏可随时选择当前页面的使用者。
2. 两位本人分别选择自己的档案，阅读并勾选云端处理说明。优先选择平时使用的音箱麦克风：点击「从音箱录入」，唤醒后按平时距离和音量朗读约 20 秒，自动更新声纹并恢复待机；也可用页面麦克风录制后上传。接口接受 5–30 秒、16 kHz 单声道 PCM。
3. 在音箱前轮流说话。每一轮重新匹配已注册声纹，不沿用前一个说话人的身份。缺失、低分、难以区分或冲突的匹配结果使用共享的原有档案；小于一秒的输入也不会自动归属个人。
4. 声纹只选择资料档案，访客与声纹匹配后的功能权限完全一致，包括音量、家居设备、Orca 电脑任务、搜索、记忆、历史、健康资料和已启用的视觉。健康资料仍使用对应档案的加密存储。识别不稳定时可在页面手动选择档案；个人档案不构成相互隔离的密码账户。

服务的短音频声纹模式假定只有一个主说话人，无法可靠检测所有重叠声音。不要两人同时讲话，也不能把成功返回一个名字当作防冒认保证。实际效果需要分别使用两人的真实声音、音箱距离及日常噪声验证。

短句模式使用 `ssd_version="200"`、`ssd_mode=2` 及声纹组。真实接口在 `utterance.attributes.voiceprint_matches` 返回 `id/name/similarity`，而 `additions.speaker_id` 可以仍是匿名编号 `"0"`。客户端读取最终包的匹配分数，要求声纹 ID 和名称都对应同一成员，最高分至少 0.5、领先第二名至少 0.1；这些是应用的初始拒识门槛，不是概率或已通过真人校准的识别率。兼容直接返回已注册名称/编号的结果，但绝不按匿名编号的顺序猜成员。

未识别身份时使用共享档案的同一助手引擎，沿用助手设置，提供相同工具，并按相同隐私设置保存共享对话及记忆。声纹匹配时改用相应个人档案；两人的资料不会因一次匹配失败被合并。不存在单独的受限访客模型，也不会再因未匹配声纹而跳过音量控制。正常语音打断和结束会话仍可用。

最近一轮只在内存保留身份判定、时长、匿名/已注册标签、成员匹配分数和回答模式。声纹诊断还提供本轮送入识别服务的整体 RMS、峰值、削波比例及判定门槛；JSON 字符串形式的服务元数据也会解析。设备状态提供当前音量 RMS、语音帧计数和最近处理错误，便于区分低音量漏检、声纹拒识与接口异常；诊断不保存原始录音或转写。收音门槛可按设备调整，不改变声纹匹配门槛。

## 数据与边界

每人有独立 SQLite、加密密钥、健康库、记忆检索索引和对话状态。旧资料继续留在“原有档案”，不自动推断归属。共享设备的对话按成员分成独立会话；声纹确认前的 ASR 接收助手名字、成员称呼，以及开启电脑控制时的公开 Orca 术语，不接收任何人的私人历史。

模型设置、助手声音和家居控制共用。新增个人档案暂不参加跨设备同步；原有档案的同步继续保留。电脑端各档案共用本机 Orca 开关、连接和默认项目；访客也可使用电脑任务工具。豆梨任务记录、请求去重和跨聊天跟踪按档案分别保存，原有记录不迁移；电脑任务页面也跟随当前档案。重启后台会恢复各档案任务的状态查询，不重复发送任务。Orca 项目中打开的会话仍是本机共享会话，可按明确要求查询、读取或继续；个人档案不是 Orca 会话的访问控制边界。安卓原生后台通话尚未接入手动档案参数，选择个人档案时使用页面语音；未声称已通过安卓或硬件验收。

注册录音仅保留在内存，通过已配置 HTTPS 设备入口上的 256 位随机链接供火山引擎下载，请求结束即撤销，最长 60 秒有效。页面关闭会停止本地录音；已提交的云端请求可能仍完成。注册音频不在本机落盘。公网入口不开放管理、健康或历史接口。

音箱录入等待下次唤醒最长 5 分钟，唤醒后单独计时 35 秒；检测到讲话后最多收集 20 秒。低于 5 秒总长、低于 3 秒有效讲话或严重削波不会提交。录入期间暂停正常 ASR/回复，避免录音混入助手声音；取消、断线和超时清除临时缓冲，已录入的声纹在云端成功更新之前仍然保留。该入口解决注册麦克风与使用麦克风不同的问题，但不能代替真人识别验收。

火山引擎会处理音频并保存云端声纹。“停用声纹”调用服务端软删除并移除本地匹配关系，不代表服务端物理删除数据。此能力的权限及收费应以实际账号控制台为准，不能从 ASR 小时包推断声纹免费。

### 两个人在同一块 ESP32 上怎么测

两位成员各自完成声纹录入，在同一后台打开「设备与家居 → 我的 ESP32」。每人说完一句，等设备卡片的「最近一次声纹判定」更新，再换人。卡片随页面约每五秒刷新；核对时间，避免误读上一句的结果。

1. **同一次唤醒里换人。** A 说「我今天给小船起名叫白帆」，B 说「我今天给小船起名叫青叶」。接着 A、B 依次问「我刚才给小船起了什么名字？」。逐句核对卡片上的成员，再分别核对回答中的名字。
2. **隔天再问。** 第一天让 A 和 B 分别要求豆梨记住两种不同的饮料偏好，并在各自档案里确认已保存。第二天用同一后台重新唤醒，两人分别问「我让你记住的饮料是什么？」。这一步检查跨会话记忆。
3. **在家里的常用位置重复。** 安静时和开着电视时各试一组，轮流说完整句子，记下大致距离。另让两人各说一次很短的「嗯」，观察是否进入访客模式。若页面时间未更新，单记为「未观察到新判定」。

每轮只需记下说话人、页面判定和回答是否属于本人。例如「A / 页面显示 B / 回答青叶」应计为认错人；「A / 页面显示 A / 回答青叶」则要检查会话或记忆检索。分别统计匹配正确、认成他人、进入访客模式和未观察到判定的次数。这里列的是待执行的真机步骤。
