# 豆包识别与家庭成员

设置 → 声音与语音可选择豆包 ASR 2.0 双向流式二遍接口。推荐地址为 `https://openspeech.bytedance.com/api/v3/sauc/bigmodel_async`，资源 ID 为 `volc.seedasr.sauc.duration`。密钥只填入应用设置，由本机密钥加密保存。

正确的助手名字、已确认词典词条作为热词发送；近期非敏感对话作为语境。只发送正确拼写，不把“老李”等误识别词加入热词。语音中的独立问候及直接称呼会按设置修正，如“再见，老李。”→“再见，豆梨。”；“我朋友老李今天来”、引述和文字输入不套用这条称呼修正。修正前的原文保留供查看。旧的助手称呼词典在迁移时改为仅限语音直接称呼。

## 两人使用

1. 设置 → 家庭成员与声纹，分别创建个人档案；侧栏可随时选择当前页面的使用者。
2. 两位本人分别选择自己的档案，阅读并勾选云端处理说明，录制 10–20 秒自然讲话，再点击上传并录入。接口接受 5–30 秒、16 kHz 单声道 PCM。
3. 在音箱前轮流说话。每一轮识别重新匹配已注册声纹，不沿用前一个说话人的身份。缺失、低分、难以区分或冲突的匹配结果进入普通对话：仍回答问题，但不会读写个人资料。小于一秒的输入也不会自动归属。
4. 识别错了或环境嘈杂时，改用页面手动选择档案。声纹是个性化入口，不是身份认证；健康档案需要在页面选择本人档案后使用。家庭成员可访问同一台本机管理页面，并非相互隔离的密码账户。

服务的短音频声纹模式假定只有一个主说话人，无法可靠检测所有重叠声音。不要两人同时讲话，也不能把成功返回一个名字当作防冒认保证。实际效果需要分别使用两人的真实声音、音箱距离及日常噪声验证。

短句模式使用 `ssd_version="200"`、`ssd_mode=2` 及声纹组。真实接口在 `utterance.attributes.voiceprint_matches` 返回 `id/name/similarity`，而 `additions.speaker_id` 可以仍是匿名编号 `"0"`。客户端读取最终包的匹配分数，要求声纹 ID 和名称都对应同一成员，最高分至少 0.5、领先第二名至少 0.1；这些是应用的初始拒识门槛，不是概率或已通过真人校准的识别率。兼容直接返回已注册名称/编号的结果，但绝不按匿名编号的顺序猜成员。

未识别身份时不再用“还没认出是谁”阻止聊天。普通对话只把本轮转写和公开运行信息交给日常模型，不发送私人提示词、任何人的历史、偏好、记忆或健康资料，不提供工具和摄像头画面；本轮语音、转写、回答不落盘，也不创建历史会话或提取记忆。每一轮独立处理，不把前一轮未知说话人的话带入下一轮。查询或修改个人资料时引导用户在页面选择自己的档案。正常语音打断和结束会话仍可用。

最近一轮只在内存保留身份判定、时长、匿名/已注册标签、成员匹配分数和回答模式。设备状态提供当前音量 RMS、语音帧计数和最近处理错误，便于区分低音量漏检、声纹拒识与接口异常；诊断不保存原始录音。收音门槛可按设备调整，不改变声纹匹配门槛。

## 数据与边界

每人有独立 SQLite、加密密钥、健康库、记忆检索索引和对话状态。旧资料继续留在“原有档案”，不自动推断归属。共享设备的对话按成员分成独立会话；声纹确认前的 ASR 只接收助手名字和成员称呼，不接收任何人的私人历史。

模型设置、助手声音和家居控制共用。新增个人档案暂不参加跨设备同步；原有档案的同步继续保留。电脑任务目前属于原有档案，新档案的模型不能读取该任务历史。安卓原生后台通话尚未接入手动档案参数，选择个人档案时使用页面语音；未声称已通过安卓或硬件验收。

注册录音仅保留在内存，通过已配置 HTTPS 设备入口上的 256 位随机链接供火山引擎下载，请求结束即撤销，最长 60 秒有效。页面关闭会停止本地录音；已提交的云端请求可能仍完成。注册音频不在本机落盘。公网入口不开放管理、健康或历史接口。

火山引擎会处理音频并保存云端声纹。“停用声纹”调用服务端软删除并移除本地匹配关系，不代表服务端物理删除数据。此能力的权限及收费应以实际账号控制台为准，不能从 ASR 小时包推断声纹免费。

## 验证

自动化覆盖请求并发隔离、健康文件与历史下载归属、未知说话人持续得到普通回答且不落入旧档案、模型请求不含个人上下文或工具、两人轮换、最终包分数匹配与低分/近分拒识、注册同意与临时链接清理。真实接口已确认两人的声纹注册及组内映射；合成语音测试验证了“你好豆梨”“再见豆梨”和正常提及“老李”的链路与样例转写，并确认短句接口实际返回匹配分数。这不代表两位真人经 ESP32 远场识别通过，仍需各自实测。
