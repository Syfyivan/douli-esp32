## Local hardware repair, 2026-10-15

- The user's Waveshare board was backed up and flashed over USB with the application partition from the official [xiaozhi-esp32 v2.5.2 release](https://github.com/78/xiaozhi-esp32/releases/tag/v2.5.2), target `waveshare-esp32-s3-audio-board`. The downloaded ZIP SHA-256 was checked against the release's `SHA256SUMS`. Wi-Fi/OTA configuration partitions were preserved. Firmware files are local ignored artifacts, not bundled application source.
- Custom wake assets reuse the official v2.4.2 board asset fonts/images and [asset packer](https://github.com/78/xiaozhi-esp32/blob/v2.4.2/scripts/build_default_assets.py). The speech model was replaced with Espressif MultiNet7 Chinese from [esp-sr commit bdd0373263718cc1bc88e4f2ec38870799d71a81](https://github.com/espressif/esp-sr/tree/bdd0373263718cc1bc88e4f2ec38870799d71a81/model/multinet_model/mn7_cn), plus FST command files from [esp-sr 2.4.7 source](https://github.com/espressif/esp-sr/tree/2f8c4b0459db5bbb39abd77adae27962d6d94bcb/model/multinet_model/fst). File Git blob hashes were verified. These models and assets retain their upstream terms; no ownership of them is claimed and they are not committed here.
- The local resource index configures `ni hao dou li` / `你好豆梨` as the wake command using upstream `CustomWakeWord`. Loading and one human-confirmed hands-free wake/spoken response are verified on real hardware; recognition quality across environments requires further trials. Reproduction scripts, provenance, logs and images are under ignored `.runtime/firmware-repair/`; the original full-flash backup is under ignored `.data/device-backups/` and contains private device configuration.
- Activation compatibility follows the firmware's status-only handling in `Ota::Activate`: the service sends empty 200/202 responses and closes the connection. A firmware update alone did not eliminate the observed teardown crash; four physical reactivation trials passed after this service change. This does not claim that every upstream networking race is fixed.

## Remote device gateway, 2026-10-16

- Firmware revision `2.5.2.2` adds authenticated HTTPS discovery scoped to the already provisioned WSS authority, retaining the same upstream base and MIT notice.
- Firmware revision `2.5.2.3` adds paired backend selection, persistent commit/rollback and private LAN fallback addresses in the same source patch. The base commit, third-party components and license notices are unchanged. Native state-machine tests compile the actual patched source with a test-only NVS implementation.
- Firmware revision `2.5.2.4` enables the existing ESP-SR device AEC path for this board, advertises `device_aec` in both transports, and clears queued playback on interruption. It uses the board's existing hardware reference channel; no vendor components or license notices are replaced.
- Remote access uses the separately installed Tailscale 1.102.2 client and its Funnel service. No Tailscale executable or credentials are redistributed. Configuration follows the official [Funnel documentation](https://tailscale.com/docs/features/tailscale-funnel) and [CLI reference](https://tailscale.com/docs/reference/tailscale-cli/funnel). The existing private Serve endpoint is preserved; a distinct public TLS port forwards only to the authenticated device gateway. See [REMOTE_ACCESS.md](REMOTE_ACCESS.md).
